# UW-00011 역할별 접근 권한 제어

> ## 1. 개요
| 항목 | 내용 |
|:-----|:-----|
| **단위업무ID** | UW-00011 |
| **단위업무명** | 역할별 접근 권한 제어 |
| **비즈니스 목적** | 역할별로 메뉴·기능·버튼 접근 범위를 차등 적용한다. VIEWER는 수정·삭제·AI 요청 UI를 숨김 처리하며, 권한 외 API 접근 시 403을 반환한다. |

## 2. 화면 목록
> 해당 없음 (전체 시스템 공통 적용)

## 3. 화면 흐름
```
[모든 화면 진입] ──▶ 프로젝트 역할 확인
  ├─ OWNER/ADMIN ──▶ 관리 권한
  ├─ MEMBER ──▶ 직무·담당자·생성자 보정시간에 따라 쓰기 허용
  └─ VIEWER ──▶ 직무와 무관하게 읽기 전용 (수정·삭제·AI 요청 UI 숨김)

[API 요청] ──▶ 백엔드 권한 검증
  ├─ 권한 있음 ──▶ 정상 처리
  └─ 권한 없음 ──▶ 403 반환
```

| 처리 | 조건 | 동작 |
|:-----|:-----|:-----|
| UI 숨김 | VIEWER 역할 | 수정·삭제·AI 요청 버튼 완전 숨김 |
| 메뉴 숨김 | MEMBER·VIEWER | 프로젝트 설정·멤버 관리 메뉴 미노출 |
| 403 반환 | 권한 외 API 접근 | 프론트 우회 접근 방어 |

## 4. 권한 정의

### 4.1 역할·직무 기본 권한

| 기능 | VIEWER | MEMBER | MEMBER + PM/PL 직무 | ADMIN | OWNER |
|:-----|:-------|:-------|:--------------------|:------|:------|
| 전체 읽기 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 스펙 생성 | ❌ | ✅ | ✅ | ✅ | ✅ |
| 스펙 내용 수정 | ❌ | 조건부 | ✅ | ✅ | ✅ |
| 스펙 삭제 | ❌ | ❌ | ✅ | ✅ | ✅ |
| 정렬·이동·담당자 변경 | ❌ | ❌ | ✅ | ✅ | ✅ |
| AI 요청 | ❌ | ✅ | ✅ | ✅ | ✅ |
| 멤버 관리 | ❌ | ❌ | ❌ | ✅ | ✅ |
| 프로젝트 삭제 | ❌ | ❌ | ❌ | ❌ | ✅ |

> VIEWER의 읽기 전용 속성이 직무보다 우선한다. 따라서 VIEWER에게 PM/PL 직무가 지정되어
> 있더라도 생성·수정·삭제·정렬·이동·담당자 변경을 허용하지 않는다.

### 4.2 핵심 스펙 수정 권한

적용 대상은 과업, 요구사항, 사용자스토리, 단위업무, 화면, 영역, 기능이다.

1. OWNER/ADMIN 또는 PM/PL 직무는 언제든 수정할 수 있다.
2. 일반 MEMBER는 대상의 가장 가까운 담당자일 때 수정할 수 있다.
3. 대상에 직접 담당자가 없으면 아래 순서로 가장 가까운 상위 담당자를 찾는다. 담당자를 하나
   찾은 시점에서 탐색을 중단하며, 그 담당자가 아닌 사용자를 더 상위 담당자라는 이유로 허용하지 않는다.
   - 요구사항: 요구사항 → 과업
   - 사용자스토리: 요구사항 → 과업
   - 단위업무: 단위업무 → 요구사항 → 과업
   - 화면: 화면 → 단위업무 → 요구사항 → 과업
   - 영역: 화면 → 단위업무 → 요구사항 → 과업
   - 기능: 기능 → 화면 → 단위업무 → 요구사항 → 과업
4. 생성자는 담당자가 아니어도 생성 시각부터 30분 동안 내용 오타를 보정할 수 있다.
5. 다른 사용자가 먼저 수정하면 남은 시간과 무관하게 생성자 보정 권한은 즉시 종료한다.
6. 생성자 보정 권한으로 일정·진척·상태를 바꿀 수 없다. 담당자 변경, 상위 항목 이동,
   표시 ID·정렬 변경은 OWNER/ADMIN 또는 PM/PL만 할 수 있다.
7. 삭제는 휴지통·복구 정책을 별도로 도입하기 전까지 OWNER/ADMIN 또는 PM/PL만 허용한다.
8. 일반 MEMBER가 새 항목을 만들 때는 이름·설명 등 내용 필드만 입력할 수 있다. 담당자,
   일정, 상태, 표시 ID, 정렬 순서는 생성 시에도 OWNER/ADMIN 또는 PM/PL만 지정할 수 있다.

### 4.3 거절 응답

API와 MCP는 403과 함께 `code`, `message`를 반환한다. 메시지는 최소한 VIEWER 읽기 전용,
생성자 30분 만료, 다른 사용자 선수정, 담당자 불일치, 상위 포함 담당자 없음, 관리자 전용 필드,
관리자 전용 삭제를 구분해야 한다. MCP는 이 메시지를 오류 결과에 그대로 노출한다.

### 4.4 구현 안전 규칙

1. 요청 본문은 엔티티별 허용 필드 스키마로 검증하며, 정의되지 않은 필드는 거부한다.
2. 생성자 보정 권한으로 저장할 때는 트랜잭션 안에서 대상 행을 잠근 뒤 30분 만료와 다른
   사용자의 선수정 여부를 다시 확인한다. 권한 확인과 실제 저장 사이의 경쟁 상태를 허용하지 않는다.
3. 본문 저장과 변경 이력 저장은 같은 트랜잭션에서 성공하거나 함께 취소되어야 한다.
4. 기존 데이터의 생성자는 추정해서 채우지 않는다. 마이그레이션 이전 행은 생성자 보정 권한 없이
   담당자·상위 담당자·관리자 규칙만 적용한다.
