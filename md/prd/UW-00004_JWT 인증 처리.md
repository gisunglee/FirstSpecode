# UW-00004 JWT 인증 처리

> ## 1. 개요
| 항목 | 내용 |
|:-----|:-----|
| **단위업무ID** | UW-00004 |
| **단위업무명** | JWT 인증 처리 |
| **비즈니스 목적** | 로그인 성공 시 Access Token(30분)과 HttpOnly Refresh Token(10일 유휴·30일 절대 만료)을 발급하고 인증 상태를 유지한다. Access Token 만료 시 RT를 원자적으로 회전하며, 다중 기기 로그인을 허용하고 로그아웃 시 해당 기기 토큰·세션만 무효화한다. |
| **관련 요구사항** | RQ-00004, RQ-00002, RQ-00003, RQ-00007 |
| **기술 스택** | JWT(HS256), HttpOnly Cookie, SameSite, Origin/Fetch Metadata, Web Locks, BroadcastChannel |

> ⚙️ **백엔드 처리 전용 단위업무** — 사용자가 직접 접근하는 UI 화면 없음. 전체 시스템 공통 인증 처리 로직으로 구성됨.

## 3. 화면 흐름
```
[로그인 성공] ──▶ AT(30분) + RT(10일) 발급, 세션 절대 만료 30일 설정
[API 요청] ──(AT 유효)──▶ 정상 처리
[API 요청] ──(AT 만료)──▶ 기존 RT 원자적 소비 + 새 AT/RT 발급 ──▶ 정상 처리
[API 요청] ──(RT 10일 미사용·30일 절대 만료·무효)──▶ 401 반환 ──▶ 로그인 화면으로 리다이렉트
[로그아웃] ──▶ 해당 기기 RT 무효화 + 세션 무효화
```

| 처리 | 조건 | 동작 |
|:-----|:-----|:-----|
| AT 발급 | 로그인 성공 시 | 만료 30분, sessionStorage 저장 |
| RT 발급 | 로그인 성공 시 | `HttpOnly; Secure; SameSite=Strict; Path=/`; 자동 로그인 선택 시 영속 쿠키·미선택 시 세션 쿠키 |
| AT/RT 자동 갱신 | AT 만료, RT·세션 유효 시 | 기존 RT 조건부 소비와 새 RT 생성을 한 트랜잭션으로 처리 |
| RT 유휴 연장 | 유효한 RT 회전 시 | 새 만료 = MIN(현재 + 10일, 세션 생성 + 30일) |
| 세션 절대 만료 | 최초 로그인 후 30일 | 활동 여부와 관계없이 RT 회전 거부, 재로그인 필요 |
| 다중 탭 갱신 | 여러 탭이 동시에 갱신할 때 | Web Lock으로 한 탭만 갱신하고 새 AT만 공유, RT는 쿠키로만 공유, 서버 경쟁 요청은 409 처리 |
| CSRF 방어 | 쿠키를 사용하는 인증 요청 | 정확한 Origin 및 Sec-Fetch-Site 동일 출처 검증, SameSite=Strict 적용 |
| 토큰 무효화 | 로그아웃 시 | 해당 기기 RT revoke_dt = NOW() 처리 |
| 세션 무효화 | 로그아웃 시 | 해당 기기 세션 invald_dt = NOW() 처리 |
| 401 반환 | AT·RT 모두 무효 시 | 클라이언트 AT 삭제 → 로그인 화면으로 리다이렉트 |

> 배포 전 Web Storage RT는 새 클라이언트가 최초 갱신 요청 body로 한 번 제출해 쿠키로 승계하고 즉시 삭제한다. 쿠키 인증 응답과 탭 간 메시지에는 RT 원문을 포함하지 않는다. 기존 클라이언트의 body RT 호환은 전환 기간 후 제거한다.

## 5. 상태 정의
| 상태 | 설명 |
|:-----|:-----|
| 유효 | AT 유효, 정상 API 접근 가능 |
| AT 만료 | AT 만료, RT로 자동 갱신 처리 |
| RT 유휴 만료 | 마지막 RT 발급 후 10일 경과, 재로그인 필요 |
| 세션 절대 만료 | 최초 로그인 후 30일 경과, 재로그인 필요 |
| 회전 충돌 | 다른 탭/요청이 같은 RT를 먼저 소비함, 409 후 승자 결과 사용 |
| 폐기 RT 재사용 | 동시성 유예 이후 폐기 RT가 다시 제출됨, 연결 세션 전체 종료 |
| 무효화 | 로그아웃으로 RT·세션 폐기, 재로그인 필요 |
