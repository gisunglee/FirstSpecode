# 일정·진척률 데이터 모델 개편 (2026-07-28)

> 다른 세션에서 이 문서 기준으로 "지금 잘 동작하는지 점검해줘" 라고 요청할 때 참고용.
> DB 마이그레이션은 완료, `tsc --noEmit` / `npm run build` 모두 통과 확인됨(코드 레벨).
> 실제 화면 조작(WBS, 대시보드, PM 등)으로 직접 확인한 것은 아님 — 여기가 점검 대상.

---

## 1. 왜 바꿨나

기존에는 단위업무(UnitWork)/화면(Screen)/영역(Area)/기능(Function) 4개 레벨에
일정·공수·진척률이 중복·산발적으로 흩어져 있었음. 특히:
- 화면에 설계 일정을 넣게 했더니, 단위업무 하나에 화면이 5~15개+ 있는 경우 화면마다
  설계 일정을 따로 입력하는 게 실무적으로 부담이었음.
- 기능에 구현 일정이 있었는데, 실제로 마감을 보는 단위는 화면이었음(기능 단위로
  마감을 따로 관리하지 않음).
- 테스트 진척률(%)을 수동 슬라이더로 입력받고 있었는데, 자동테스트 연동이 없는 한
  이 숫자는 의미가 없었음.

세 차례에 걸쳐 정리:
1. **1차**: 단위업무/화면/기능 전반의 일정·공수 소유권 재배치 (아래 표 참고)
2. **2차**: 화면의 설계 일정(시작일/종료일/공수) 3필드를 완전히 제거하고 단위업무로 일원화
3. **3차**: 테스트 진척률(test_rt)을 UI/API 전체에서 제거 (DB 컬럼만 보존)

## 3. 진척률 롤업 규칙 (변경 없음, 참고용)

```
기능(design_rt, impl_rt)  ← 담당자가 슬라이더로 직접 입력 (leaf, source of truth)
   ↓ 평균 롤업
화면 avgDesignRt/avgImplRt  ← lib/pm/progressRollup.ts: fetchScreenProgress
   ↓ 평균 롤업
단위업무 designRt/implRt   ← lib/pm/progressRollup.ts: fetchUnitWorkProgress
```
공수 가중평균이 아니라 **단순 평균**(의도적 — 추후 바뀔 수 있음, 바뀌면 `progressRollup.ts` 한 곳만 고치면 전체 반영).

## 5. 다음 세션에서 점검할 때 확인 포인트

아래 화면/기능을 실제로 열어서 **에러 없이 뜨는지 + 숫자가 말이 되는지** 확인 필요:

- [ ] **WBS** (`/wbs`) — UNIT_WORK/SCREEN/FUNCTION × DESIGN/IMPL phase 전체 조합. 특히 SCREEN의
      DESIGN phase가 단위업무 계획설계기간을 잘 상속해서 보여주는지
- [ ] **대시보드** (`/dashboard`) — 정체된 일 카드(`설계 {designDelayedCount}`), 마감 임박 카드
- [ ] **PM 화면** (`/pm`) — 지연 현황 매트릭스(설계=단위업무 1컬럼, 구현=단위업무/화면/영역/기능),
      기준일 변경(`asOf`)까지 눌러서 재계산 확인
- [ ] **화면 편집** (`/projects/[id]/screens/[screenId]`) — 설계 필드 없이 구현 일정만 뜨는지,
      영역 목록의 설/구 뱃지(테스트 뺀 2개만)
- [ ] **기능 편집** (`/projects/[id]/functions/[functionId]`) — 상단 진척률이 설계/구현 2개만
      뜨는지(테스트 슬라이더 없어야 함), 구현 공수만 있고 날짜 입력란 없는지
- [ ] **영역 상세/영역 목록** — 설/구 2개 뱃지, 테스트 컬럼 없는지
- [ ] **기능 목록** — "100점 🎉" 완료 배지가 설계+구현 100%만으로 판정되는지
- [ ] **My Task / My Work** — 화면 행의 시작일/종료일이 단위업무 값으로 보이는지, 공수 칸이
      기능에서만 편집 가능한지
- [ ] **엑셀 내보내기** — 화면/기능/영역 3종 모두 테스트(%) 컬럼 없이 정상 다운로드되는지
- [ ] **단위업무 상세** — 계획설계 시작일/종료일/공수 입력이 여기서만 되는지

에러가 나오면 **어느 화면에서, 어떤 조작(필터/조회/저장)을 했을 때, 어떤 에러 메시지**였는지
같이 알려주면 바로 원인 좁혀서 고칠 수 있음.
