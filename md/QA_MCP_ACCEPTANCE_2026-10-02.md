# 배포 후 확인 — 테스트용 명세서에서 수행

1. **연결:** 화면과 단위업무를 함께 연결 → 저장 → 다시 열어 저장. 두 연결이 유지되고 단위업무의 ‘테스트 명세’ 메뉴에 표시되어야 함. 화면만 연결한 명세도 그 화면의 소속 단위업무 메뉴에 표시되어야 함.
2. **MCP 수정:** 회차 시작 전 전제조건·데이터·계정을 입력 → MCP에 예상결과만 수정 요청. 나머지 값이 유지되어야 함. `update_test_spec`으로 개요·연결을 바꿔도 케이스 수·내용은 동일해야 함.
3. **미실행:** 새 회차 시작 → ‘미실행’ 표시 확인 → 바로 종료 시 차단. 모든 항목을 합격 또는 해당없음으로 판정하면 종료되어야 함.
4. **이력:** 종료된 회차의 케이스 수정·삭제 시 저장이 차단되어야 함. 다시 조회하고 결과서를 내려받아 기존 문장과 판정이 동일한지 확인. 변경할 테스트는 새 명세서로 작성.

기존 완료 회차의 NA는 유지한다. 기존 진행중 회차에서 적용 대상인데 판정 일시가 없는 NA는 미실행으로 표시하므로 판정을 다시 선택한다.

로컬 검증: 회귀 11개 + 엑셀 8개 통과. DB 마이그레이션 없음. 운영 배포 및 실제 DB 동시성 검증은 하지 않음. 전체 타입 검사는 기존 결제 관련 오류 7개로 미통과.
